# Wave 2, product web app lane: implementation plan

> Read `2026-11-21-wave2-README.md` first: it lists what is frozen and the constraints every lane shares.

**Goal:** the screen a judge sees: the circuit from the mat drawn live, the tutor's line and prediction buttons, the learner's concept map, and the mouse ticking with the current under the fingertip.

**Architecture:** every pixel is a function of the latest `State` in the `useTacto` store. No circuit data is copied into component state and no physics runs in the browser. Small components, one job each, grouped by feature.

**Tech stack:** React 19, TypeScript strict, Tailwind, zustand, `motion` (all installed). No new dependencies: the four parts are drawn as standard schematic symbols in plain SVG.

## What you consume

- `web/src/contract.ts` (frozen): `State`, `Circuit`, `Part`, `Wire`, `Probe`, `Tutor`. New fields this wave: `Wire.overloaded`, `Circuit.topology`, `Probe.buzz`, `Tutor.lesson_id`, `step_index`, `step_count`, `correct`, `feedback`, `hint`.
- `web/src/useTacto.ts`: `useTacto()` gives `{ connected, state, send }`; `useTactoConnection(onHaptic)` opens the socket once. You may edit this file.
- `web/src/haptics/driver.ts` (frozen): `DRIVERS`, `HapticsDriver` with `connect`, `play`, `playRaw`, `isConnected`, `close`.
- Develop against `make bench`, which serves a mock world at `http://localhost:5173`. The mock is a single lit bulb with a prediction on screen; it does not exercise every state, so build each component to be driven by props and check the other states by hand with temporary values you then remove.

## Behaviour

**Bench.** The grid is `GRID_COLS = 9` by `GRID_ROWS = 6` dots (a placeholder until the paper kit's geometry is final; one constant, with a `TODO(vision owner)`). Wires are lines between dots. A part is drawn between its `a` and `b` dots at any angle. The fingertip is a ring at `probe.x, probe.y` (0..1 of the mat) when `probe.present`.

- A wire carrying current shows moving dashes whose speed follows `|current|` and whose direction follows its sign; a dead wire is a plain dim line; an `overloaded` wire is drawn hot orange and pulsing.
- A bulb's glow follows `brightness` smoothly (animate, do not jump). At 0 it is clearly off.
- A switch shows open or closed from `closed`.
- `status === 'short'` must be unmistakable from two metres away.
- Nothing in the bench hard-codes a layout: it must draw any list of parts and wires.

**Tutor panel.** The prompt is always on screen as large text. In `predict`, one large button per choice sends `{ type: 'answer', choice, via: 'button' }`. In `test` and `explain`, a Next button sends `{ type: 'next' }`. `feedback` appears above the explanation when set. `hint` appears when set. Progress reads "Step 2 of 5" from `step_index + 1` and `step_count`; hide it when `step_count` is 0. After an answer, show whether it was right once the phase is `explain` (not before: the learner should see the result on the mat first).

**Concept map.** One node per entry in `state.learner`, coloured by mastery (`unseen`, `shaky`, `solid`), with the concept id shown as words (`closed_loop` → "Closed loop"). It must render with zero entries.

**Wheel.** Accumulate `deltaY` into steps of `WHEEL_UNITS_PER_STEP = 40` and send `{ type: 'wheel', steps }`; scrolling up raises the voltage (the sign was confirmed on the demo laptop: `remainder += event.deltaY`). Listen passively.

**Haptics.** The mouse needs one click to connect: a "Connect mouse" button in the status bar connects the `webhid` driver and shows the state; without it the `console` driver is used so everything still runs. While `probe.present`: `probe.buzz` → repeat `BUZZ_WAVEFORM = 3` every `1000 / BUZZ_HZ` ms with `BUZZ_HZ = 25`; otherwise tick at `min(probe.pulse_hz, MAX_PULSE_HZ)`; zero means silent. Server `haptic` messages play their pattern through the same driver. All calls go through `HapticsDriver`.

**Always.** The page renders something sensible when `state` is `null` and when disconnected. Large type and high contrast: this is projected. No chat box and no text input.

## Tasks

There is no web test runner, and adding one is the project owner's decision, so each task ends with `make check` passing and a manual check in the browser against `make bench`. Keep logic that can be a pure function (grid maths, wheel accumulation, pulse period) in plain `.ts` files so it can be unit-tested later.

1. **Grid and bench skeleton.** `grid.ts`, `Bench.tsx` drawing dots, the mock's wires and the fingertip.
2. **Parts.** The four symbols and `PartView`; bulb glow; switch states.
3. **Live wires.** Current animation; overloaded style; short state.
4. **Tutor panel and concept map.**
5. **Wheel and haptics.** `useVoltageWheel`, `HapticsContext`, `useProbeHaptics`, status bar.
6. **App layout.** Assemble; check null state, disconnected state and a narrow window.

Commit after each.

## Review focus

- Fifteen `State` messages a second must not re-create timers or restart animations when nothing relevant changed.
- A part whose two dots are the same, or a wire of zero length, must not produce `NaN` in the SVG.
- Leaving the page or losing the socket must stop any ticking.
- Buttons must not double-send when clicked twice quickly.
- Every colour that carries meaning (mastery, short) must also differ in something other than hue.
