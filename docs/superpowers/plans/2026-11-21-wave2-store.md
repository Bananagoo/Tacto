# Wave 2, store and lesson content lane: implementation plan

> Read `2026-11-21-wave2-README.md` first: it lists what is frozen and the constraints every lane shares.

**Goal:** lesson content written as YAML, validated, and kept in a local database together with learners, their progress and their prediction attempts.

**Architecture:** YAML in `lessons/` is the authoring format. A loader turns a file into the frozen `Lesson` model. SQLite, through SQLModel, stores lessons, the concept graph and learner data behind the two repository interfaces in `tacto/store/repositories.py`. Nothing outside `store/` sees a table or a session.

**Tech stack:** SQLModel (installed), PyYAML, pydantic. No new dependencies.

## Interfaces you produce

```python

class LessonFileError(ValueError): ...            # message names the file and the problem
def load_lesson(path: Path) -> Lesson: ...
def load_lessons(directory: Path) -> list[Lesson]: ...   # every *.yaml, sorted by file name

# tacto/store/db.py
DEFAULT_DATABASE_URL = "sqlite:///data/tacto.db"   # relative to server/; data/ must be gitignored
def create_database(url: str = DEFAULT_DATABASE_URL) -> Engine: ...   # creates tables; idempotent

# tacto/store/lessons.py
class SqlLessonRepository:        # satisfies repositories.LessonRepository
    def __init__(self, engine: Engine) -> None: ...

# tacto/store/learners.py
class SqlLearnerRepository:       # satisfies repositories.LearnerRepository
    def __init__(self, engine: Engine) -> None: ...

# tacto/store/seed.py
def seed_lessons(repository: LessonRepository, directory: Path) -> list[str]: ...  # lesson ids saved
```

`Lesson`, `Progress`, `Attempt` and the two repository protocols are frozen in `tacto/lessons/models.py`, `tacto/learner/models.py` and `tacto/store/repositories.py`. Read them before starting.

## Tables

| Table | Columns |
|---|---|
| `lesson` | `id` (pk), `title`, `language`, `position`-free; plus `content_hash` so reseeding an unchanged file is a no-op |
| `lesson_step` | `lesson_id` + `position` (pk), `step_id`, `body` (the step as JSON) |
| `concept` | `id` (pk), `title`, `lesson_id` |
| `concept_prerequisite` | `concept_id` + `requires_id` (pk) |
| `learner` | `id` (pk, autoincrement), `nickname` (unique), `created_at` |
| `mastery` | `learner_id` + `concept_id` (pk), `mastery`, `correct`, `wrong` |
| `completed_step` | `learner_id` + `lesson_id` + `step_id` (pk), `position` (order finished) |
| `attempt` | `id` (pk), `learner_id`, `lesson_id`, `step_id`, `choice`, `correct`, `at` |

A lesson read back from the database must equal the lesson that was saved (`Lesson` equality). Saving a lesson again replaces its steps and its concepts and prerequisites, in one transaction.

## Lesson content

Write `lessons/circuits-101.yaml` from the lesson table in the spec: a setup step plus four steps (`setup`, `close_the_loop`, `series`, `parallel`, `short`). The mat is a 6 V battery, bulb A, a gap the learner draws across, a slot where a wire tile can be swapped for bulb B (series), and a side branch with an empty slot for bulb B (parallel).

- Concepts and prerequisites: `closed_loop`; `current` requires `closed_loop`; `voltage` requires `closed_loop`; `resistance` requires `current`; `series` requires `current` and `resistance`; `parallel` requires `current` and `voltage`.
- Step order inside a step is predict → build → test → explain. Give `series` and `parallel` a prediction with the known wrong ideas from the spec as `misconceptions`. Also give `close_the_loop` a prediction ("When you close the gap, will you feel anything in the mouse?"). `setup` and `short` have none.
- `done_when` per step: `setup` `{status: open, bulbs: 1}`; `close_the_loop` `{status: closed, lit_bulbs: 1}`; `series` `{topology: series, lit_bulbs: 2}`; `parallel` `{topology: parallel, lit_bulbs: 2}`; `short` `{status: short}`.
- Follow `.claude/rules/lessons.md` exactly: every spoken line is one sentence under 20 words, second person, no symbols or units that read badly aloud, no praise inflation; hints are a ladder of three that never state the answer; vibration is current and the wheel is voltage, never mixed.
- The wording is a draft for the lesson author to edit. Put a comment at the top of the file saying so.

## Tasks

Each task: write the tests, watch them fail, implement, watch them pass, commit.

1. **Loader.** Tests: the real `lessons/circuits-101.yaml` loads and has five steps in the order above; a file that is not valid YAML, a file whose top level is not a mapping, and a file that fails validation each raise `LessonFileError` naming the file; `load_lessons` returns lessons sorted by file name and ignores non-YAML files.
2. **Lesson content.** Tests (on the loaded real file): every `say`, hint and misconception line is a single sentence of fewer than 20 words; no line contains a digit followed by a unit letter or the symbols `Ω`, `=`, `/`; every step with a prediction has 2–4 choices and at least one misconception; each step has exactly three hints; no hint contains its step's answer word.
3. **Database and lesson repository.** Tests (each on a fresh `sqlite://` in-memory engine): save then get returns an equal `Lesson`; `get` of an unknown id is `None`; saving a changed lesson replaces steps and drops removed concepts; `list_ids` is sorted; `concept_graph` returns every concept with its requirements; `create_database` twice on the same file does not fail or lose data (use `tmp_path`).
4. **Learner repository.** Tests: `get_or_create` returns the same id for the same nickname and different ids for different ones; nicknames are trimmed and compared case-insensitively, and an empty nickname is rejected with `ValueError`; a new learner's progress is an empty `Progress`; save then load returns an equal `Progress`, including the order of `completed_steps`; saving twice does not duplicate rows; attempts come back oldest first with timezone-aware times; progress and attempts of two learners do not mix.
5. **Seeding.** Tests: `seed_lessons` on the real `lessons/` directory saves `circuits-101`; running it twice leaves one lesson; a bad file raises `LessonFileError` and saves nothing from that file.

Add `server/data/` to `.gitignore` (this one shared file you may edit, that line only).

## Review focus

- A learner nickname with unusual characters (quotes, emoji, very long) must be stored and returned exactly, never break a query.
- Two saves of the same lesson in a row must not leave orphan steps or prerequisites.
- A database file from an earlier run must still open after a code change that adds nothing to the schema.
- Times must survive a round trip without shifting zone.
- No SQL built by string formatting.
