# Wave 2, simulation lane: implementation plan

> Read `2026-11-21-wave2-README.md` first: it lists what is frozen and the constraints every lane shares.

**Goal:** turn the parts and wires on the mat into a fully solved `Circuit`, and turn the current under the fingertip into what the mouse should do.

**Architecture:** a graph step decides whether there is anything to solve (empty, open, short, closed). Only closed circuits go to ngspice, through InSpice. A feel step maps current to a pulse rate. All of it is pure functions over the contract models.

**Tech stack:** networkx, InSpice + ngspice (both already installed). No new dependencies.

## Files

| File | Responsibility |
|---|---|
| `server/tacto/sim/__init__.py` | Exports `solve_circuit`, `probe_for` |
| `server/tacto/sim/graph.py` | Build the electrical graph; classify empty / open / short / closed; find the shorted path |
| `server/tacto/sim/engine.py` | The one place that talks to ngspice: netlist in, node voltages out |
| `server/tacto/sim/solver.py` | `solve_circuit`: graph → engine → filled-in `Circuit` (currents, voltages, brightness, topology) |
| `server/tacto/sim/feel.py` | `pulse_hz`, `probe_for` |
| `server/tests/sim/test_*.py` | Tests, hand-worked answer in each docstring |

## Interfaces you produce

```python
# tacto/sim/solver.py
def solve_circuit(parts: Sequence[Part], wires: Sequence[Wire], source_voltage: float) -> Circuit: ...

# tacto/sim/feel.py
def pulse_hz(current_amps: float) -> float: ...
def probe_for(circuit: Circuit, *, present: bool, x: float, y: float, on: str | None) -> Probe: ...
```

`Part`, `Wire`, `Circuit`, `Probe`, `Topology` come from `tacto.contract`. Inputs are never mutated; return new models.

## Behaviour

**Graph.** Every dot `(col, row)` is a node. A wire joins its two dots. A part sits between its `a` and `b` dots. A closed switch conducts like a wire; an open switch is a break. The battery's `a` is its positive terminal.

**Status.**
- `empty`: no parts.
- `open`: there is no battery, or no conducting path from the battery's `a` round to its `b`.
- `short`: a path joins the battery's terminals through wires and closed switches only. This wins over everything else: nothing is solved, every part's `current`, `voltage` and `brightness` are 0, `total_current` is 0, and every wire on a zero-resistance path between the terminals has `overloaded=True`.
- `closed`: otherwise.

**Solving.** Model each wire and closed switch as a 1 mΩ resistor so every wire gets its own current; bulbs and resistors as fixed resistances (`BULB_OHMS = 10.0`, `RESISTOR_OHMS = 10.0`). Give ngspice only the part of the graph connected to the battery; anything else keeps zero current. Run one operating-point analysis. Working call (checked on this project):

```python
from InSpice.Spice.Netlist import Circuit as SpiceCircuit
from InSpice.Spice.Simulator import Simulator
from InSpice.Unit import u_Ohm, u_V

c = SpiceCircuit("tacto")
c.V("bat", "n0", c.gnd, 3 @ u_V)
c.R("bulb", "n0", c.gnd, 10 @ u_Ohm)
analysis = Simulator.factory().simulation(c, temperature=25, nominal_temperature=25).operating_point()
float(analysis.nodes["n0"][0])        # 3.0
float(analysis.branches["vbat"][0])   # -0.3 (current out of the + terminal reads negative)
```

`circuit.simulator()` from older PySpice examples raises "Deprecated API"; do not use it. Compute each element's current from the node voltages across it.

**Finding ngspice.** The library path comes from `NGSPICE_LIBRARY_PATH`. If it is unset, look in `/opt/homebrew/lib/libngspice.dylib`, `/usr/local/lib/libngspice.dylib` and `/usr/lib/x86_64-linux-gnu/libngspice.so.0`, and set the variable before InSpice is imported. If none exists, raise an error that says to run `brew install libngspice`. Import InSpice lazily, create the simulator once, and guard it with a lock: ngspice is one shared, non-thread-safe instance. Its two start-up warnings (no `spinit`, unsupported version) are harmless.

**Filling in the result.**
- `Part.current` and `Wire.current` are signed a → b. `Part.voltage` is the drop across the part; the battery's is `source_voltage`.
- `total_current` is the current through the battery, positive.
- `brightness` (bulbs only) follows power: `min(1.0, power_watts / FULL_BRIGHT_WATTS)` with `FULL_BRIGHT_WATTS = 3.6` (one bulb at 6 V). Two bulbs in series at 6 V must come out clearly dim (0.25 each), not half.
- `topology`: `none` when no bulb carries current; `single` for one lit bulb; `series` when every lit bulb carries the battery's full current; `parallel` when every lit bulb has the full source voltage across it; otherwise `mixed`. Compare with a relative tolerance of 1%.
- A `source_voltage` of 0 with a closed loop is `closed` with zero currents; do not call the engine.

**Feel.**
- `pulse_hz(current_amps)`: 0 for no current (below `MIN_CURRENT_AMPS = 0.005`), otherwise `HZ_PER_AMP * abs(current_amps)` with `HZ_PER_AMP = 5.0`. It must be proportional, with no offset: the lesson depends on half the current feeling like exactly half the rate. With these values one bulb at 6 V ticks at 3 Hz, two in series at 1.5 Hz, and the battery wire of the parallel circuit at 6 Hz, which is the web side's cap. Do not cap it here.
- `probe_for`: `on` is a part id or `"wire:c,r-c,r"` (the wire's `a` then `b` dots; match either direction). Not `present`, or `on` is `None` or unknown → a silent probe with `present`, `x`, `y` passed through. On an overloaded wire of a shorted circuit → `buzz=True`, `pulse_hz=0`. Otherwise `current` is that element's current and `pulse_hz` its rate.

## Tasks

Each task: write the tests, watch them fail, implement, watch them pass, commit.

1. **Graph and status** (`graph.py`). Tests: empty mat; battery alone is open; a gap in the loop is open; an open switch is open and closing it is closed; a wire straight across the battery is short; a short drawn across a lit two-bulb circuit is short and names the overloaded wires, and wires off that path are not overloaded.
2. **Engine** (`engine.py`). Tests: the one-resistor example above; a clear error when the library path points nowhere (patch the search list, do not uninstall anything).
3. **Solver** (`solver.py`, layout below, 6 V, bulbs 10 Ω). Tests, each with its arithmetic in the docstring:
   - One bulb: 0.6 A everywhere, bulb drop 6 V, brightness 1.0, topology `single`, status `closed`.
   - Two in series: 0.3 A everywhere, 3 V each, brightness 0.25 each, `series`.
   - Two in parallel: 0.6 A in each bulb, 1.2 A through the battery and the battery wires, brightness 1.0 each, `parallel`.
   - Kirchhoff: at the parallel junction the wire currents sum to zero.
   - Sign: reversing a wire's `a` and `b` flips the sign of its current.
   - A bulb on a dead-end stub off a lit loop has zero current and the loop is still solved.
   - Short: all zero, status `short`.
   - Inputs are not mutated.
4. **Feel** (`feel.py`). Tests: zero and tiny currents are silent; doubling the current exactly doubles the rate (0.3 A → 1.5 Hz, 0.6 A → 3.0 Hz); negative current gives the same rate as positive; `probe_for` on a part, on a wire in either direction, on an unknown id, not present, and on an overloaded wire.

Use this layout in tests (dots are `(col, row)`): battery `a=(0,1)` `b=(0,3)`; top wire `(0,1)→(4,1)`; bulb A `a=(4,1)` `b=(4,3)`; bottom wire `(4,3)→(0,3)`. Build the series and parallel variants from it with small helper functions in `server/tests/sim/conftest.py`.

## Review focus

- A circuit ngspice cannot solve (floating node, zero-resistance loop) must never reach it.
- Two parts or wires on the same pair of dots (parallel wires) must not crash or double-count.
- A wire from a dot to itself, or a part with `a == b`, must be ignored, not crash.
- Repeated calls must be fast: one solve under 5 ms after the first.
- Results must not depend on the order of `parts` or `wires`.
